# 有效的交易日志

日志不是流水账。一份有效的日志能回答：**我在什么情况下赚钱、在什么情况下亏钱、为什么。**

## 记录的三个层次

| 层次 | 内容 | 本项目字段 |
|---|---|---|
| 客观数据 | 时间、品种、方向、价格、R | `date` `time` `symbol` `entry` `stop` `target` `exit` |
| 决策依据 | 为什么做这笔：bias、流动性、PD Array、模型 | `htfBias` `drawOnLiquidity` `liquiditySweep` `pdArrays` `setup` |
| 心理与执行 | 情绪、信心、是否按计划、犯了什么错 | `emotions` `confidence` `followedPlan` `mistakes` `grade` |

大多数人只记第一层，但真正的改进来自第二、三层。

## 好的复盘 vs 差的复盘

| 差 | 好 |
|---|---|
| 「亏了，市场太难做」 | 「入场前没有扫流动性，我在 inducement 处就进场了」 |
| 「止损被打掉了」 | 「止损放在 FVG 内而不是摆动低点外，位置不符合规则」 |
| 「下次要更有耐心」 | 「下次必须等 5m 出现 MSS 后才入场」 |

好的复盘：**具体、可验证、可转化为规则**。

## 交易正文模板的用法

- **交易前：计划** —— 入场前写（至少写几个关键词），防止事后合理化
- **交易中：执行** —— 实际执行与计划的差异
- **交易后：复盘** —— 做对了什么、做错了什么
- **一句话教训** —— 越短越好，方便以后翻看

## 截图规范

每笔交易建议 2–3 张，放到 `journal/screenshots/`，文件名与交易 id 对应：

- `2026-10-27-nq-01-htf.png`：HTF 背景（DOL、PD Array）
- `2026-10-27-nq-01-entry.png`：入场周期（流动性被扫、MSS、FVG、入场 / 止损 / 目标）
- `2026-10-27-nq-01-after.png`：结果（可选）

## 从数据到行动

日志的价值在于改变行为。每次复盘都要落到一个具体动作：

| 仪表盘发现 | 可能的行动 |
|---|---|
| 某个 setup 期望值长期为负 | 暂停该 setup，回到回放中重新验证 |
| 某时段表现差 | 计划中删去该时段 |
| 违反计划的交易期望值显著为负 | 强化检查清单；违反一次当天停止 |
| 盈利单兑现率低 | 检查是否过早移动止损或提前离场 |
| 平均亏损明显大于 1R | 检查是否移动止损、扛单 |
| B / C 级交易拖累整体 | 只做 A / A+ |
| 某种情绪下期望值为负 | 加入规则：该情绪状态下不交易 |
| 错过的机会潜在 R 很高 | 处理恐惧：降低仓位，先恢复扣扳机的能力 |

## 保持诚实

- 不删除亏损交易，不修改事后不利的数据
- 错误标签宁可多记，不要少记
- 「没有记录」本身就是一个信号：通常是最不想面对的那笔交易
